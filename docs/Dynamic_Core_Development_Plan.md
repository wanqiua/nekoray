复核后的开发计划，2026-09-13。适用当前 Nekoray 3.26 二开版本、Matsuri Xray 1.8.4 和 sing-box 1.14.0，首版验收平台为当前便携包面向的 Windows 10/11 x64。技术事实见[评估报告](SingBox_Features_and_Dynamic_Core_Assessment.md)。本文件保留开发前确定的范围与验收要求；当前实现和验证状态见[实现说明](Dynamic_Core_Implementation.md)。

**首个完整版本的目标：用户照常导入、双击连接和批量测试；只在有需要时手动选核。选核、测试、订阅更新、失败恢复及基础 TUN 切换一起交付。**

原计划按底层模块和新增协议排序，容易出现“能切换，但测速仍要求分组、更新订阅会丢选择、开着 TUN 不能直接切”的半成品。调整后按完整的日常使用流程验收；新协议放在这个流程稳定之后。

**默认行为与主界面**

| 用户动作或状态 | 计划中的行为 | 用户需要额外做什么 |
| --- | --- | --- |
| 更新软件、加载旧配置 | 旧节点缺省为自动；默认优先内核沿用当前选择；节点、分组、订阅和本地设置保留 | 无需重新导入或重新选核 |
| 导入节点或更新订阅 | 新节点自动判断可用内核；同一节点保留原手动偏好 | 无需按内核建立不同分组 |
| 双击节点或按 Enter | 构建目标配置、准备内核并连接，界面保持打开 | 延续现有操作 |
| 在主界面选中一个节点 | 节点旁显示“自动 / Xray / sing-box”互斥按钮，以及选择理由 | 选择节点后一次点击即可设定偏好 |
| 为未运行的节点选核 | 只保存该节点的偏好，说明“下次连接生效” | 不会意外切换正在使用的节点 |
| 为当前运行节点选核 | 自动完成必要的停止、启动和状态更新 | 无需先断开或重启界面 |
| 批量修改选中节点 | 右键“内核”设置下次连接的偏好，包括其中正在运行的节点；按能力逐项处理，汇总“已保存，当前连接保持” | 不对每个节点弹框，不打断当前连接 |
| 修改默认优先内核 | 只影响自动模式下后续连接，不立即打断当前连接 | 不必重启软件 |
| 开着 TUN 切换节点或内核 | 程序管理 TUN 与代理的切换，保留开关、DNS 和路由意图 | 无需手动“关 TUN → 切核 → 开 TUN” |

按钮作用于当前选中的节点，旁边显示节点名称，避免把“当前选中”和“正在运行”混淆。多选时使用批量菜单；编辑窗口复用同一偏好字段，不再增加另一套优先级。首版不加入分组级选核覆盖，减少设置继承层级。

当前连接即时切换由单节点按钮执行；批量修改仅保存下次偏好。若修改策略后仍解析到同一核心及同一有效配置，只更新偏好，不重启连接。

只有一个内核支持时，自动选它，禁用无效按钮并就近说明原因，例如“此节点使用 HTTPUpgrade，将使用 sing-box”。正常自动选择不弹确认框。两边都支持时尊重手动偏好；自动模式使用默认优先内核。

保存的偏好、准备使用的内核、实际运行的内核、测试所用内核分别记录：

- 未连接：内核栏可显示“自动 → sing-box”，表示预计选择，不能显示为正在运行。
- 已连接：运行区显示“正在使用 sing-box”，只在目标实例启动确认后更新。
- 测试结果：显示“128 ms · sing-box”，详情可看时间和另一内核的历史结果。
- 偏好因订阅或版本变化失效：保留用户偏好并标注“暂不适用”；确实只有另一内核完整支持时自动选择它，并显示这次实际选择。不能把旧偏好伪装成已执行。

手动选择后，若目标内核启动失败，应恢复原运行配置；没有更新的选择时，一并恢复原界面选择。已有更新的选择时，先完成恢复，再处理最新意图，避免旧回调覆盖新选择。若恢复也失败，明确显示“已断开”。后台不会因为一次 URL 超时就悄悄改选另一个内核；可以提供“重试测试”或“测试另一内核”，后者只测试，不改变当前连接和保存的偏好。

切换可能使已有连接重连，这一点放在按钮的简短说明中。正常切换不弹重复确认；删除节点等原有破坏性操作仍保留确认。

**测速应帮助判断，不制造新的误判**

默认批测每个节点只使用按策略选定的一个内核，不要求先分组，不默认把所有节点测两遍。两个内核共享现有的一个总并发上限，避免“设置 10，实际启动 20 个请求”。“两核对比测试”放在可选菜单中，只对双方完整支持的节点提供。

选中节点的单次 URL 测试和批量 URL 测试使用同一套“下次连接将采用的配置和内核”。专门的“测试当前连接”使用已保存的实际运行上下文，标注为当前连接测试。更改默认内核或批量偏好后，这两者可能不同，不能共用一个含义不明的延迟。主列表排序和移除候选以“下次连接”的有效结果为准。

| 结果类别 | 主界面表达 | 是否可被“移除不可用”选中 |
| --- | --- | --- |
| 成功 | 延迟 + 实际测试内核 | 否 |
| 远端连接、认证或证书测试失败 | “连接失败”，展开后有具体原因 | 仅当前配置和当前有效选核下的明确失败可作为候选，仍由用户确认删除 |
| 内核或界面暂不支持该组合 | “暂不支持”，说明缺少的能力 | 否 |
| 内核缺失、未就绪或运行异常 | “内核异常”，提供检查/重试入口 | 否 |
| 取消或任务已过期 | “已取消”或历史标记，保留上次有效结果 | 否 |
| 尚未测试当前内核 | “未测试”；另一内核结果可在详情中查看 | 否 |

结果有效性至少绑定实际生成的测试配置、相关 DNS/TLS 等设置、测试 URL/模式/参数及内核构建标识。修改这些内容或更新核心后，旧结果只能作有来源的历史；从旧版迁移而来的无可信来源延迟也按历史处理，不参与当前排序和删除候选。

历史延迟不能冒充切换后内核的结果。取消、编辑节点、修改偏好、删除、订阅替换和内核重启都应使相应旧任务失效，进程代次用于拒绝过期回调。批测不启停正在使用的主代理；正常切换也不应为退出整个核心进程而连带杀掉另一批测试。

已有两个相关入口必须在首版一起改：当前[测试结果写回](../ui/mainwindow_grpc.cpp) 把所有错误统一写成负延迟，[移除不可用](../ui/mainwindow.cpp) 则按负延迟删除。这种表示不能直接承载新增的能力错误和内核错误。

**订阅和设置的兼容要求**

选核偏好是本地节点元数据，不是协议字段，也不参与节点的协议配置相等判断。订阅更新应先解析到临时结果、建立身份对应关系，再一次提交；“更新前清空”也必须先保存可匹配的本地偏好。解析失败或没有有效结果不能先把旧组清空，导入摘要需要说明无法识别的条目数量和原因。

匹配优先使用订阅提供的稳定标识；没有稳定标识时，只对同组内唯一、可靠的协议身份进行匹配。显示名称、列表位置和可复用的本地数字 ID 都不能单独充当身份。重复、重排或仅改名的同一节点应尽量保留偏好；无法可靠对应的条目回到自动，并在更新摘要说明，不把别人的偏好套过去。

现有[订阅更新](../sub/GroupUpdater.cpp) 在某分支解析前删除节点，另有[首个匹配项判断](../sub/GroupUpdater.cpp) 使用 deleted_index > 0，需要修正。现有[匹配键](../db/ProfileFilter.cpp) 取自 bean；新偏好不能直接加入这个匹配键。

两套旧核心设置和路由文件均保留。公共监听端口、代理模式、用户配置的证书验证策略和可共同表达的 DNS/分流规则，应形成当前操作的一份明确上下文；切核不能无意采用另一套旧文件中的不同设置。内核专属 JSON、脚本和规则保留归属，不能静默丢弃或放宽安全字段。不能保持语义的组合应在停止旧代理前提示具体设置冲突。

**内部实施顺序与对外交付**

| 阶段 | 主要工作 | 阶段完成条件 |
| --- | --- | --- |
| A：先消除切换风险 | 梳理能力矩阵及 GUI 可表达范围；明确公共设置和内核专属设置；为两个包装内核补本地配置预检和能力信息；验证现有外部 TUN 的复用路线 | 能区分协议不支持、GUI 字段缺失、依赖缺失、配置错误和模式冲突；确认目标配置不会改变原有 DNS/路由/TLS 意图 |
| B：普通代理的完整操作流程 | CoreManager 管理独立进程/RPC/端口/token；主界面选核；可恢复的切换；混合批测、结果分类、统计、导出和订阅偏好一起完成 | 普通代理与系统代理下，导入→连接→切核→测试→订阅更新→重启软件的操作可连续完成 |
| C：基础 TUN 切换 | 优先复用已有独立 sing-box TUN → SOCKS 路径；覆盖现有内置 TUN 的转换或受控重启；按 PID/句柄管理进程 | TUN 开着也能按同样操作切核；DNS/FakeIP/IPv4/IPv6/分流和权限状态通过验证，异常可恢复 |
| **R1：首个完整版本** | A–C 全部通过并完成配置迁移、包验证 | 用户日常使用不再需要了解或手动启停内核进程；只有普通代理完成时属于预览，不作为完整首版交付 |
| D：新增常用协议 | AnyTLS、Snell，以及 Hysteria2 的必要新选项；每项同时完成导入、编辑、自动选核、测试、导出和订阅更新 | 常用操作入口完整且有真实服务端互通验证，不以“内核能解析”作为发布标准 |
| E：按需要扩展 | SSH、ShadowTLS 组合、WireGuard 专用编辑；NaiveProxy/OpenVPN/OpenConnect/Tailscale；保留旧连接的切换 | 分别评估使用需求、依赖、认证、运行状态和回归成本 |

阶段 A–C 是内部实施顺序，混合批测、订阅持久化和基础 TUN 不再是首版之后才补的功能。新协议不能抢先扩大第一版的范围。新增协议的常规编辑界面只展示服务器、认证及必要的 TLS/版本选项；复用、指纹、算法和高级混淆默认折叠，导入能取得的字段自动填充。

**技术实现必须满足的约束**

- 当前共享 RPC 没有配置检查或能力查询方法。新增预检必须使用与实际启动一致的目标配置，且不占用公共代理监听、不修改系统路由；它不能证明远端服务器可用。未知构建不能直接按版本号乐观认定支持。
- 按“解析选核意图 → 准备目标核心进程并确认 RPC 就绪 → 核实能力、构建并预检目标配置 → 停止旧代理实例 → 启动目标 → 更新状态”串行切换。预检失败时保留旧代理运行；启动失败时回滚到已保存的完整运行上下文。已建立会话的断开不可逆；不得将回滚描述为恢复原 TCP/TLS 会话。
- 连续点击不同内核时，准备阶段可以合并到最后一次选择，已开始的端口/TUN 交接按顺序完成或回滚，再处理用户最后一次意图。每次意图带独立代次，旧请求的成功、失败和回滚回调不能覆盖更新的偏好或界面。仅在没有更新意图时，失败回滚才恢复该次操作前的界面选择。不能用“请重启软件”弹窗代替正常超时、取消和恢复处理。
- 每个核心实例和 TUN 辅助进程都有独立所有权。停止或恢复一个实例不能按可执行文件名杀掉其他实例；现有按名停止逻辑必须先改，包含其他安装目录运行的 Nekoray。
- 当前配置上下文要贯穿生成器、进程、RPC、测速、统计、导出与 UI；工作线程不能临时改全局 coreType 来生成另一内核的配置。
- 支持矩阵同时检查核心和 GUI 适配器。首批应修正 SOCKS4 版本生成、SOCKS/HTTP 的 TLS/传输限制，以及 KCP、QUIC 等不能丢失的参数；尚未能完整表达的组合保留节点并说明原因。
- 对 TUN 复用现有授权与辅助进程，普通切换不要求用户手动关开 TUN。首次需要的系统权限仍按平台正常申请；不承诺绕过系统授权。不能为了让切核成功而关闭 TUN、FakeIP 或绕过既有分流。

**首版用户场景验收**

| 场景 | 验收重点 |
| --- | --- |
| 旧配置直接升级 | 节点/分组 ID、订阅、原参数和设置保留；缺省自动仍按原默认内核连接；迁移可回退 |
| 一个分组包含 SS/VLESS/Hysteria2/TUIC 和单核专属组合 | 不必分组或切全局设置，导入、连接、批测都选对内核 |
| 已选中但未运行的节点修改偏好 | 当前连接保持，偏好保存，下次连接生效 |
| 正在使用的双核兼容节点切换 | 一次选择完成切换；显示真实内核；原设置保持；失败恢复，恢复失败如实显示断开 |
| 带内核专属规则、插件、自定义 JSON 的节点 | 不能保持完整语义时，在停止旧代理前说明原因；不通过丢字段制造“兼容” |
| 两核混合批测并发、取消、同时切核 | 共用总并发上限；主代理不受测试影响；结果带来源；取消和过期不污染显示及删除候选 |
| 先 Xray 测试，再切 sing-box，再排序/移除不可用 | 旧结果仅作历史；不误删暂不支持、内核异常、已取消或仅另一内核测试失败的节点 |
| 改 DNS/TLS、测试 URL、升级核心或迁移旧延迟 | 有效性正确失效；历史来源可查看，不参与当前排序与删除候选；当前连接测试和下次连接测试能区分 |
| 订阅首项、重排、重名、仅改名、“更新前清空”、无效返回 | 同一节点偏好保留；不会串配；失败不清空旧组；有效更新仍遵守既有分组目标 |
| 已开启 TUN 或系统代理后切核、切换途中失败 | 用户开关与意图保留；TCP/UDP、DNS/FakeIP、IPv4/IPv6 和分流回归通过；不残留路由、端口或失控进程 |
| 多个安装目录同时运行、某个核心崩溃、退出软件 | 仅操作本实例拥有的进程；不影响其他安装；统计与 UI 不被闲置核心状态覆盖 |
| 修改默认内核、批量设偏好、连续点击 | 操作对象明确；不意外启动未运行节点或批量打断连接；旧回滚不覆盖新选择；同一有效配置不重启；汇总可理解 |

验证分层进行：能力及设置转换测试 → 本地真实代理/RPC/GUI 操作 → 隔离环境中的系统代理和 TUN 测试 → 干净目录与旧配置副本的包验证。用户当前正在运行的代理和真实配置不作为自动测试环境。

本轮推荐确定的首版范围为 **R1**；AnyTLS/Snell 等新增协议紧随其后。基础切换完成前不投入 Dashboard、自动按速度反复换核或“所有连接无缝迁移”等额外功能。
